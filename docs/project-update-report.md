## 기능과 데이터 보호

- 관련 글 기본 3개 제한을 제거해 프로젝트 상세에서 전체 글을 읽는 순서로 탐색한다. 기존 withChurch 네 번째 글도 노출된다.
- 글마다 같은 시리즈의 이전/다음 이동, metadata, 태그, Markdown 코드·표와 출처 링크를 확인했다.
- D1 없는 런타임은 Markdown 번들을 읽는다. D1에서는 초기 marker와 별개로 slug별 이력을 사용하는 insert-only 등록을 한다.
- v2 기존 글의 삭제를 복구하지 않고 관리자 편집·초안·작성자·시각·slug/id 소유권을 보존한다. 신규 글의 후속 삭제도 이력으로 보호한다.
- 시리즈 순서가 기존 글과 충돌하면 그 신규 글을 건너뛰고 로그에 알린다. 기존 데이터를 자동 변경하지 않는다.
- 상세 설계·재실행 정책은 [증분 등록 문서](./incremental-post-seeding.md)에 있다.

브라우저 검사는 로컬 production 서버와 캐시된 Chromium 129에서 수행했다. 스크린샷과 측정 JSON은 로컬 `outputs/browser-qa/`에 있다(검토용, Git 제외). Safari/Firefox 및 실제 iOS/Android 기기 검증은 수행하지 않았다.

D1 통합 시험은 설치된 workerd가 지원하는 호환 날짜 2026-05-22를 사용했다. 운영 런타임/CDN과 같은 환경이라고 주장하지 않는다. Cloudflare 운영 DB에 등록되는 것은 이후 정상 배포에서 첫 접근 시이며 이번에는 실행하지 않았다.

## 최종 검사 중 정리한 기존 문제

- 관리자 API의 nullable validation 결과는 data null 검사로 narrowing했다.
- 게시글 category는 허용 목록의 find 결과로 타입과 실제 필터를 맞췄다.
- Cloudflare D1·환경 모듈 타입과 vinext가 사용하는 표준 Request/Response 자산 fetch 계약을 명시했다.
- GNU timeout이 없는 macOS에서도 빌드 제한을 유지하도록 Node의 bounded spawn fallback을 추가했다.
- 의존성 변경이나 기존 lockfile 재생성은 하지 않았다.

## 통합·제외 및 남은 확인

- 모든 후보 조사와 통합 결정: [조사 기록](./project-content-audit.md).
