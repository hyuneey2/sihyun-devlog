이분 탐색은 정렬된 배열에서 특정 값을 찾는 알고리즘으로 처음 배웠다. 유데미 강의의 이분 탐색 파트를 공부하면서 배열에 정답이 직접 들어 있지 않아도, **정답이 될 수 있는 범위가 정렬된 성질을 가지면** 이분 탐색을 적용할 수 있다는 것을 알게 됐다.

## 문제: 백준 2805 나무 자르기

[백준 2805번 나무 자르기](https://www.acmicpc.net/problem/2805)는 절단기의 높이 H를 정해 나무를 자르고, 필요한 길이 M 이상을 가져갈 수 있는 가장 높은 H를 구하는 문제다.

절단기 높이와 가져가는 나무 길이의 관계는 다음과 같다.

- H를 낮추면 더 많은 나무를 가져간다.
- H를 높이면 가져가는 나무가 줄어든다.

즉 H가 커질수록 조건을 만족하기 어려워지는 단조성이 있다.

```text
조건 만족: 0, 1, 2, ... H
조건 불만족: H + 1, H + 2, ...
```

우리가 찾는 값은 조건을 만족하는 구간의 가장 오른쪽 값이다.

## 풀이 과정

1. 절단기 높이의 최솟값을 0, 최댓값을 가장 높은 나무로 둔다.
2. 중간 높이 `mid`에서 얻는 나무 길이를 계산한다.
3. 길이가 M 이상이면 더 높은 절단기도 가능한지 오른쪽을 탐색한다.
4. 길이가 M보다 작으면 절단기를 낮추기 위해 왼쪽을 탐색한다.
5. 조건을 만족한 높이 중 가장 큰 값을 저장한다.

## 최종 코드

```python
import sys

input = sys.stdin.readline

n, required = map(int, input().split())
trees = list(map(int, input().split()))

left = 0
right = max(trees)
answer = 0

while left <= right:
    height = (left + right) // 2
    wood = 0

    for tree in trees:
        if tree > height:
            wood += tree - height

    if wood >= required:
        answer = height
        left = height + 1
    else:
        right = height - 1

print(answer)
```

## 코드 리뷰

```python
left = 0
right = max(trees)
```

절단기 높이는 0보다 작을 수 없고 가장 높은 나무보다 높게 설정할 이유도 없다. 이 범위 안에 정답이 반드시 존재한다.

```python
height = (left + right) // 2
```

현재 범위의 중간 높이를 검사한다. 가능한 높이 범위를 매번 절반으로 줄인다.

```python
if tree > height:
    wood += tree - height
```

절단기보다 높은 나무에서만 잘린 부분이 생긴다. `max(tree - height, 0)`으로도 표현할 수 있지만 조건문이 계산 의도를 더 분명하게 보여 줬다.

```python
if wood >= required:
    answer = height
    left = height + 1
```

필요한 양을 확보했다면 현재 높이는 가능한 답이다. 하지만 가장 높은 절단기 높이를 찾아야 하므로 답을 저장하고 오른쪽 범위를 계속 확인한다.

높이 범위를 줄이는 데 `O(log H)`, 한 높이에서 모든 나무를 확인하는 데 `O(N)`이 필요해 전체 시간복잡도는 `O(N log H)`다.

## 트러블슈팅

### 나무 길이가 충분할 때 어느 방향으로 가야 하는지 헷갈렸다

구하려는 값이 나무 길이가 아니라 **절단기 높이의 최댓값**이라는 점을 다시 적었다. 나무를 충분히 얻었다면 절단기를 더 높여도 되는지 확인해야 하므로 `left = height + 1`이다.

### 길이가 정확히 M일 때 바로 종료했다

정확히 M을 얻은 높이가 있어도 더 높은 높이에서 우연히 같은 양을 얻거나 조건을 계속 만족할 수 있다. 문제는 최대 높이를 요구하므로 `wood == required`에서도 오른쪽 탐색을 계속해야 한다.

### `while left < right`에서 마지막 후보를 놓쳤다

닫힌 구간 `[left, right]`을 사용했으므로 두 값이 같을 때도 그 후보를 검사해야 한다. 반복 조건을 `left <= right`로 두고, 범위를 바꿀 때는 `height ± 1`을 사용해 무한 반복을 막았다.

### 모든 높이를 순서대로 확인하면 왜 안 될까

절단기 높이를 0부터 1씩 올리면 높이 범위가 큰 입력에서 너무 많은 검사가 필요하다. 조건 만족 여부가 한 방향으로만 바뀐다는 단조성을 이용하면 검사 횟수를 로그 단위로 줄일 수 있다.

## 정리

이 문제를 통해 이분 탐색은 값 하나를 찾는 문법이 아니라, **조건을 만족하는 경계값을 찾는 방법**이라는 점을 이해했다. 이후에는 정답 후보가 숫자 범위이고, 후보가 커질수록 조건 결과가 한 방향으로 바뀌는지를 먼저 확인하고 있다.
