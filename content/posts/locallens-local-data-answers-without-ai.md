LocalLens는 서버 에이전트의 데이터 질의응답을 제공한다. 하지만 백엔드 전체 장애에서 계산과 보고서 일부를 브라우저로 유지하더라도 AI 요청은 성공할 수 없다. 2026년 11월 #16은 질문 창을 닫는 대신 현재 자료와 계산값을 찾는 제한된 조회 모드로 바꿨다. 이 기능을 브라우저 AI나 로컬 언어 모델이라고 부르지는 않는다.

## 서버가 필요 없다는 말의 범위를 좁혔다

localAnswer는 지역 data, state, judge, plans, snapshot과 dataSource를 받는다. 이미 받은 실제 지역 자료와 화면이 계산한 값이 조회 대상이다. 자체 학습 모델, 외부 검색, 새로운 최적화 계산은 없다.

```text
질문 문자열
→ 마을 이름 / 정해 둔 질문 종류 매칭
→ 현재 판정·대안·출처에서 값 읽기
→ 지원 범위 안의 문장 또는 미지원 안내
```

서버 정상인데 agent:false인 상태는 입력을 막고 안내하는 경로이며, 연결 불가나 Snapshot 사용 중 자료 조회로 바뀌는 경로와 구분한다. 서버 계산까지 정상인 모든 상황에서 무조건 로컬 조회로 전환하는 것은 아니다.

## 질문이 있어도 결과가 없을 수 있다

지원 예시는 공백 인구, 달성률, 비용, 배치, 세 안의 차이, 계산 기준과 출처다. 대안을 아직 만들지 않았다면 비용이나 달성률을 임의로 채우지 않고 먼저 예산안 만들기를 지나야 한다고 알린다.

판정이 없는 화면으로 직접 들어온 경우는 같은 실제 자료와 기준으로 judgeLocal을 계산할 수 있다. 출처 답변에는 Snapshot 사용 여부와 수집일을 함께 적고 수집일이 원본 통계 기준일과 다름을 남긴다.

비용 답변도 연 비용과 설치비를 분리하고 단가가 가정값이라는 사실을 표시한다. '정답'처럼 보이는 문장에서도 원래 화면의 단위와 출처를 유지해야 한다.

## 제한된 매칭은 제한된 기능이다

현재 구현은 마을 이름을 먼저 찾고, 출처·안 비교·배치·달성률·비용·공백·기준 순으로 정규식을 검사한다. 첫 매칭 규칙이 답하므로 여러 의도를 섞은 질문은 모두 해석하지 못한다. 짧은 마을 이름이 여러 읍면에 겹치면 자연어 문맥을 완전하게 구분하는 기능도 아니다.

이를 해결한 AI 이해 능력이 있는 것처럼 설명하지 않고, 지원 질문 예시를 코드가 처리할 수 있는 것만 제공했다. 모르는 질문은 supported:false와 함께 현재 범위를 알린다. 조회 함수는 사용자의 예산이나 공급수단 상태를 바꾸지 않는다. '예산을 두 배로 바꿔 줘' 같은 명령 실행 에이전트가 아니다.

## 같은 숫자라도 계산 출처를 남겼다

서버 대안과 추정 대안은 결과 문장에 출처를 표시한다. 현재 조회는 plans의 estimate 정보와 화면에 있는 결과를 사용한다. 별도의 숫자를 만들어 서버 응답처럼 꾸미지 않는 것이 원칙이다.

다만 현재 문구 중 공백 설명은 의료 접근 중심으로 작성되어 있고, 규칙 기반 질문에는 복합 의도·문맥 한계가 있다. 모든 서비스 선택과 모든 질문을 동일하게 설명한다고 확대할 수는 없다. 이 글은 현 구현의 범위를 기록하며 그런 한계를 새로 해결했다고 쓰지 않는다.

## 검증 근거

localAnswer.test.ts는 조회 종류와 미지원 질문 등을 확인하는 근거이고, offline-snapshot 문서는 전체 장애 최초 방문 시나리오의 자료 조회 전환을 기록한다. 2026-11-07의 로컬 브라우저 검증이며, 정상 서버의 비용이 드는 /api/ask는 그 검증에서 호출하지 않았다.

이번 블로그 작업에서도 AI 운영 요청을 보내지 않았다. 장애 대응에서 기능 이름과 사용자 기대를 낮추는 것이 필요했다. 생성형 AI가 없어진 상황을 감추는 대신, 사용할 수 있는 데이터와 답할 수 있는 범위를 드러낸 구현이다.
