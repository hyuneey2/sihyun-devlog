LocalLens는 농어촌의 의료·교통 접근성을 진단하고 한정된 예산의 공급 대안을 비교하는 팀 프로젝트다. 이전 이름은 VillageCoverage이며 2026년 10월 #11에서 브랜드를 정리했다. 나는 프론트엔드 요구사항·표현·API 검증을 다루며 '지도에 수치를 보여 준다'는 말 안에 서로 다른 계산과 가정이 있다는 점을 확인했다. 서버 최적화 알고리즘을 직접 구현한 작업은 아니다.

## 72개 지역이라는 범위를 먼저 설명했다

서비스는 전국 72개 지역의 마을 자료를 다룬다. 2026-11-10 기준 README가 설명하는 공개 정적 자료는 59개 지역이다. 나머지 13개는 서버 정상 시 지원하며, 전체 장애 때 쓸 수 있는 자료를 임의로 만들어 채우지 않는다. 이 두 범위를 프로젝트 소개에서도 구분했다.

마을 인구, 시설, 교통, 가까운 시설까지의 시간은 서버 자료의 칸이다. 프론트는 그것을 지도 레이어, 진단 카드, 조건 입력과 대안 비교로 연결한다. 원자료의 기준일과 정적 파일의 수집일도 다르므로 같은 날짜로 표기해서는 안 된다.

## 브라우저 판정이 서버를 대체하는 것은 아니다

기준 슬라이더를 움직일 때마다 서버 응답을 기다리면 지도 반응이 늦어진다. judgeLocal은 현재 지역 자료와 기준으로 마을 상태를 바로 계산한다. 서버 judge 응답이 오면 같은 조건의 결과인지 key를 확인하고 마을 id별 판정과 합계를 비교한다. 다르면 서버 결과를 표시하고 불일치가 드러나도록 한다.

```text
자료 + 사용자 기준 → 즉시 브라우저 판정 → 지도
                         ↑
같은 조건 서버 판정 → 비교 → 다르면 서버 결과 사용
```

코드의 판정 규칙은 서버 응답에 맞춰 확인한 규칙이다. 모든 규칙이 공공기관의 공식 기준이라는 뜻은 아니다. 자가용 탭의 판정과 시설 종류 필터는 서버와 동일한 API 결과가 아니라 화면 계산인 범위도 있다.

## '갈 수 없음'도 같은 이유가 아니다

병원 가는 길은 마을 안 시설, 자가용 기준 시간, 버스 접근 조건을 나눠 본다. 마을 안 병의원이 있으면 갈 수 있는 것으로, 시설이 너무 멀면 상태 2, 버스 조건을 충족하지 못하면 상태 1로 나눈다. 버스 이용 서비스는 의료시설 거리와 별개다.

정밀 지역은 정류장 접근성에 더해 하루 운행과 읍내행 첫차 조건을 확인하고, 간이 지역은 해당 자료가 없어 정류장 조건 중심으로 본다. 자료가 부족한 곳에 정밀 분석과 같은 확실성을 부여하지 않도록 설명해야 했다. 지역 등급의 개수도 고정 소개문 대신 서버 값을 쓰는 경로가 있다.

## 지도 색이 측정값처럼 보이지 않게 했다

MapLibre와 deck.gl의 시간 격자는 실제 격자마다 도로 시간을 측정한 결과가 아니다. 가까운 마을의 시설 이동 시간을 거리 가중으로 퍼뜨린 그림이다. 주민 수가 없는 칸이나 마을에서 먼 칸은 옅게 표시한다. 랜딩의 3D 격자 역시 마을 자료를 집계한 시각화다.

대안의 순회 노선도 정류장 사이의 직선이며 실제 도로 경로가 아니다. 선과 색은 직관적이어서 오히려 숫자보다 확정적인 정보로 읽힐 수 있다. 범례와 tooltip에 이러한 표현의 한계를 남겼다.

## 공공 기준과 팀 가정을 함께 보여 주기

의료·교통 취약도는 서버 지표를 프론트의 점수식으로 조합한 부분이 있다. data-audit는 가중치와 걷는 시간 기준에 팀 예시값이 포함된다고 설명한다. 응급 지표, 기준 인구, 의사 수 비교 기준과 같은 원천도 각각 다르다. 하나의 '정부 기준 점수'로 표현하지 않았다.

#12와 #14는 프로젝트 정보와 데이터 활용·출처 페이지를 정리했다. 데이터가 많아질수록 별도 설명 페이지가 부가 정보가 아니라 결과를 해석하는 진입점이 되었다. 이번 글 작성에서는 현재 코드·문서와 해당 PR을 대조했으며 서버 자료를 새로 수집하거나 운영 지도를 검증하지는 않았다.
