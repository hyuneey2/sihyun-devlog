유데미 강의의 완전탐색 파트에서는 가능한 경우를 전부 확인하는 여러 방법을 배웠다. 처음에는 완전탐색을 느리고 단순한 풀이로 생각했지만, 실제로는 **입력 범위가 허용한다면 가장 확실한 풀이**가 될 수 있었다.

## 완전탐색을 쓰기 전에 계산한 것

완전탐색 문제에서는 바로 반복문부터 작성하지 않고 다음 순서로 확인했다.

1. 선택 가능한 경우의 수를 계산한다.
2. 각 경우마다 수행하는 연산 수를 확인한다.
3. 최대 입력에서도 충분히 작다면 전부 탐색한다.
4. 경우의 수가 크다면 중복 계산을 줄일 방법을 찾는다.

예를 들어 N개 중 두 개를 고르는 경우는 `N × (N - 1) / 2`개다. N이 9라면 36개뿐이지만 N이 백만이라면 모든 쌍을 확인할 수 없다. 같은 이중 반복문이라도 입력 크기에 따라 가능한 풀이인지가 달라진다.

## 문제: 백준 2309 일곱 난쟁이

[백준 2309번 일곱 난쟁이](https://www.acmicpc.net/problem/2309)는 아홉 명의 키가 주어졌을 때, 키의 합이 100이 되는 일곱 명을 찾는 문제다.

일곱 명을 직접 고르면 `9C7`이고, 반대로 제외할 두 명을 고르면 `9C2`다. 두 값은 모두 36으로 같지만, 제외할 두 명을 찾는 쪽이 조건을 더 단순하게 표현할 수 있다.

```text
전체 키의 합 - 제외할 두 명의 키 = 100
```

따라서 제외할 두 명의 합은 `전체 합 - 100`이어야 한다.

## 풀이 과정

1. 아홉 명의 키를 모두 더한다.
2. 서로 다른 두 인덱스 `i`, `j`를 고른다.
3. 두 사람을 제외한 합이 100이면 두 인덱스를 저장한다.
4. 저장한 두 사람을 제외하고 오름차순으로 출력한다.

## 최종 코드

```python
heights = [int(input()) for _ in range(9)]
total = sum(heights)
excluded = None

for i in range(8):
    for j in range(i + 1, 9):
        if total - heights[i] - heights[j] == 100:
            excluded = (i, j)
            break

    if excluded is not None:
        break

answer = [
    height
    for index, height in enumerate(heights)
    if index not in excluded
]

answer.sort()
print(*answer, sep="\n")
```

## 코드 리뷰

```python
for i in range(8):
    for j in range(i + 1, 9):
```

`j`를 `i + 1`부터 시작해 같은 사람을 두 번 고르지 않고, `(i, j)`와 `(j, i)`도 중복해서 확인하지 않는다.

```python
if total - heights[i] - heights[j] == 100:
```

매번 남은 일곱 명의 합을 새로 구하지 않고, 미리 계산한 전체 합에서 두 값을 뺀다.

```python
if excluded is not None:
    break
```

안쪽 반복문에서 `break`를 실행해도 바깥 반복문은 계속된다. 정답을 찾은 뒤 두 반복문을 모두 끝내기 위해 바깥에서도 한 번 더 종료 조건을 확인했다.

경우의 수는 36개로 고정되어 있어 탐색 비용은 매우 작다. 일반화하면 두 명을 고르는 탐색은 `O(N²)`이고, 정렬은 `O(N log N)`이다.

## 트러블슈팅

### `break` 한 번으로 탐색이 끝나지 않았다

처음에는 정답을 찾은 직후 안쪽 반복문에서만 `break`를 사용했다. 그러면 바깥 반복문이 다음 `i`로 넘어가 다시 탐색하고, 이후 다른 쌍으로 값이 바뀔 수 있다. 찾은 값을 `excluded`에 저장하고 바깥 반복문에서도 종료하도록 수정했다.

### 키가 같은 사람이 있다면 값으로 제거해도 될까

값 자체를 기준으로 `remove()`를 두 번 호출하면 동작할 수 있지만, 같은 키가 있을 때 어떤 사람을 제외하는지 코드만 보고 판단하기 어렵다. 탐색에서 찾은 **인덱스**를 저장하고 그 인덱스만 제외하는 방식이 더 명확했다.

### 일곱 명을 조합으로 고르는 방법과 무엇이 다른가

`itertools.combinations(heights, 7)`을 사용해도 통과한다. 다만 이 문제에서는 전체 합에서 두 명을 제외하는 식이 조건을 더 직접적으로 보여 준다. 완전탐색에서도 가능한 방법 중 문제의 조건을 간단히 만드는 방향을 선택할 수 있었다.

## 정리

완전탐색은 무조건 비효율적인 방식이 아니다. 일곱 난쟁이처럼 경우의 수가 작다면 모든 가능성을 확인하는 것이 구현도 단순하고 정답도 확실하다. 이 파트를 공부한 뒤에는 `O(N²)`이라는 표기만 보고 포기하지 않고, 실제 최댓값을 대입해 연산 횟수부터 계산하게 됐다.
