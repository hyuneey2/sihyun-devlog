동적 계획법 파트에서는 코드를 외우기보다 점화식을 세우는 과정을 연습했다. DP는 큰 문제를 작은 문제로 나눌 수 있고, 같은 작은 문제가 반복해서 등장할 때 계산 결과를 저장해 재사용하는 방식이다.

문제를 읽고 바로 `dp` 배열을 만드는 대신 다음 내용을 먼저 적었다.

1. `dp[i]`가 무엇을 의미하는가
2. 이전에 구한 어떤 값으로 `dp[i]`를 만들 수 있는가
3. 가장 작은 초기값은 무엇인가
4. 계산 순서는 이전 값이 먼저 준비되도록 되어 있는가

## 문제: 백준 1463 1로 만들기

[백준 1463번 1로 만들기](https://www.acmicpc.net/problem/1463)는 정수 N에 다음 연산을 사용해 1을 만드는 최소 횟수를 구한다.

- 3으로 나누어떨어지면 3으로 나눈다.
- 2로 나누어떨어지면 2로 나눈다.
- 1을 뺀다.

처음에는 가능한 경우마다 3으로 나누는 연산을 우선하면 될 것 같았다. 하지만 10에서는 다음 반례가 생긴다.

```text
2로 나누기 우선: 10 → 5 → 4 → 2 → 1 (4회)
1을 먼저 빼기: 10 → 9 → 3 → 1 (3회)
```

당장 숫자를 크게 줄이는 선택이 전체 연산 횟수를 최소로 만들지는 않는다. 따라서 가능한 이전 상태의 답을 모두 비교해야 한다.

## 상태와 점화식

`dp[i]`를 i를 1로 만드는 최소 연산 횟수라고 정의했다.

어떤 i에서도 1을 빼는 연산은 가능하므로 기본값은 다음과 같다.

```text
dp[i] = dp[i - 1] + 1
```

i가 2로 나누어떨어지면 2로 나눈 상태도 비교한다.

```text
dp[i] = min(dp[i], dp[i / 2] + 1)
```

i가 3으로 나누어떨어지면 3으로 나눈 상태도 비교한다.

```text
dp[i] = min(dp[i], dp[i / 3] + 1)
```

## 최종 코드

```python
n = int(input())

dp = [0] * (n + 1)

for number in range(2, n + 1):
    dp[number] = dp[number - 1] + 1

    if number % 2 == 0:
        dp[number] = min(dp[number], dp[number // 2] + 1)

    if number % 3 == 0:
        dp[number] = min(dp[number], dp[number // 3] + 1)

print(dp[n])
```

## 코드 리뷰

```python
dp = [0] * (n + 1)
```

인덱스와 숫자를 일치시키기 위해 N + 1 크기의 배열을 만든다. `dp[1]`은 이미 1이므로 연산 횟수 0이 그대로 초기값이 된다.

```python
for number in range(2, n + 1):
```

작은 숫자부터 순서대로 계산한다. `dp[number]`를 구할 때 필요한 `dp[number - 1]`, `dp[number // 2]`, `dp[number // 3]`이 이미 계산되어 있다.

```python
dp[number] = dp[number - 1] + 1
```

모든 숫자에서 가능한 연산으로 먼저 값을 채운다. 이후 나누기 조건이 성립하면 더 작은 값으로 갱신한다.

각 숫자에서 상수 개의 비교만 수행하므로 시간복잡도는 `O(N)`, 배열을 저장하는 공간복잡도도 `O(N)`이다.

## 트러블슈팅

### `if` 대신 `elif`를 사용했다

6처럼 2와 3으로 모두 나누어떨어지는 수는 두 경우를 모두 비교해야 한다. `elif`를 사용하면 앞 조건이 참일 때 뒤 조건을 확인하지 않으므로 각각 독립된 `if`로 작성했다.

### 배열을 큰 값으로 초기화해야 하는지 고민했다

이 문제에서는 모든 수에서 `1 빼기`가 가능하다. 따라서 `dp[number - 1] + 1`이라는 유효한 값을 먼저 넣은 뒤 나누기 결과와 비교할 수 있어 별도의 무한대 초기값이 필요하지 않았다.

### 재귀로 모든 경우를 확인했더니 느렸다

N에서 가능한 연산을 재귀로 모두 시도하면 같은 숫자에 도달하는 경로가 반복된다. 메모이제이션을 추가할 수도 있지만, 필요한 작은 값의 순서가 명확해 아래에서 위로 채우는 반복문 풀이가 더 단순했다.

### 가장 많이 나누는 것이 최선이라고 생각했다

10의 반례를 직접 적어 보니 그리디 선택이 성립하지 않는 이유가 분명해졌다. DP 문제에서는 하나의 직관적인 선택만 따르기보다, 현재 상태로 올 수 있는 여러 이전 상태를 비교해야 한다.

## 정리

DP에서 가장 어려운 부분은 반복문이 아니라 `dp[i]`의 의미를 한 문장으로 정하는 일이었다. 상태 정의가 분명하면 초기값, 점화식, 계산 순서가 자연스럽게 이어졌다. 이후 DP 문제에서는 코드를 쓰기 전에 상태와 점화식을 먼저 종이에 적고 있다.
