그리디 파트를 공부하기 전에는 눈앞에서 가장 큰 값을 고르면 되는 문제라고 생각했다. 하지만 지역적으로 좋아 보이는 선택이 전체 결과도 최적으로 만든다는 근거가 없으면 그리디 풀이가 아니다.

스터디에서는 다음 두 질문에 답할 수 있을 때 그리디를 적용했다.

- 지금 한 선택을 나중에 되돌릴 필요가 없는가?
- 다른 최적해도 지금 선택을 포함하는 형태로 바꿀 수 있는가?

## 문제: 백준 2812 크게 만들기

[백준 2812번 크게 만들기](https://www.acmicpc.net/problem/2812)는 N자리 숫자에서 K개의 숫자를 지워 가장 큰 수를 만드는 문제다.

같은 자릿수의 두 수를 비교하면 앞자리 숫자가 큰 쪽이 항상 더 크다. 따라서 뒤에 더 큰 숫자가 나타났을 때, 앞에 있는 작은 숫자를 지울 수 있다면 지우는 것이 유리하다.

예를 들어 `4177252841`에서 앞부분을 보면 다음과 같이 선택한다.

```text
4 다음에 1이 등장: 4 유지
7 등장: 앞의 1 제거
제거 횟수가 남아 있고 4 < 7: 4도 제거
```

앞에서부터 필요한 숫자만 스택에 남기면, 이미 확인한 구간의 최선 상태를 계속 유지할 수 있다.

## 풀이 과정

1. 숫자를 왼쪽부터 한 자리씩 확인한다.
2. 제거 횟수가 남아 있고 스택의 마지막 숫자가 현재 숫자보다 작으면 제거한다.
3. 더 제거할 수 없거나 마지막 숫자가 현재 숫자 이상이면 현재 숫자를 넣는다.
4. 모든 숫자를 확인한 뒤에도 K가 남았다면 뒤에서 남은 개수만큼 제거한다.

## 최종 코드

```python
n, k = map(int, input().split())
number = input().strip()

stack = []
remove_count = k

for digit in number:
    while stack and remove_count > 0 and stack[-1] < digit:
        stack.pop()
        remove_count -= 1

    stack.append(digit)

if remove_count > 0:
    stack = stack[:-remove_count]

print("".join(stack))
```

## 코드 리뷰

```python
while stack and remove_count > 0 and stack[-1] < digit:
```

세 조건이 모두 필요하다.

- 스택이 비어 있지 않아야 마지막 값을 비교할 수 있다.
- 삭제 가능 횟수가 남아 있어야 한다.
- 현재 숫자가 더 클 때만 앞의 숫자를 지운다.

```python
stack.pop()
remove_count -= 1
```

작은 앞자리 하나를 제거할 때마다 사용할 수 있는 삭제 횟수도 함께 줄인다.

```python
if remove_count > 0:
    stack = stack[:-remove_count]
```

숫자가 전체적으로 내림차순이면 `while` 조건이 거의 실행되지 않는다. 이때는 앞자리를 유지하고 뒤에서 제거해야 가장 큰 수가 된다.

각 숫자는 스택에 한 번 들어가고 많아야 한 번 빠진다. 중첩 반복문처럼 보이지만 전체 연산은 `O(N)`이다. 스택에는 최대 N개의 숫자를 저장하므로 공간복잡도는 `O(N)`이다.

## 왜 이 선택이 안전한가

현재 숫자보다 작은 숫자가 앞에 있고 그 숫자를 제거할 수 있다고 하자. 작은 숫자를 그대로 두는 결과와 제거해 현재 숫자를 더 앞으로 옮기는 결과를 비교하면, 처음 달라지는 자리에서 후자가 더 크다. 뒤의 숫자가 어떻게 이어져도 이 차이는 뒤집히지 않는다.

따라서 앞의 작은 숫자를 제거하는 선택은 나중에 후회할 필요가 없다. 이 성질 덕분에 매 단계의 선택이 최종적으로 가장 큰 수를 만든다.

## 트러블슈팅

### `if`로 한 번만 제거했더니 틀렸다

현재 숫자 하나가 앞의 여러 작은 숫자를 모두 밀어낼 수 있다. `if`를 사용하면 마지막 숫자 하나만 비교하고 끝나므로, 조건을 만족하는 동안 계속 제거하는 `while`이 필요했다.

### 내림차순 입력에서 K개를 다 지우지 못했다

`987654`처럼 앞 숫자가 계속 큰 경우에는 스택에서 제거할 일이 없다. 반복이 끝난 뒤 `remove_count`가 남아 있는지 확인하고 뒤쪽을 잘라야 한다.

### `stack[:-remove_count]`가 빈 배열이 됐다

파이썬에서 `remove_count`가 0일 때 `stack[:-0]`은 전체가 아니라 빈 리스트다. 그래서 반드시 `if remove_count > 0:` 조건 안에서만 슬라이싱했다.

## 정리

이 문제에서 배운 것은 스택 구현보다 그리디의 선택 근거였다. 앞자리의 영향이 더 크고, 작은 앞자리를 큰 현재 숫자로 바꾸는 선택은 이후 결과로 뒤집히지 않는다. 그리디 문제를 풀 때는 코드보다 먼저 이 선택이 왜 안전한지 설명해 보고 있다.
