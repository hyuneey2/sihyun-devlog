TAB 학회 코딩테스트 스터디에서는 유데미 강의를 따라 자료구조부터 다시 공부했다. 배열, 스택, 큐의 정의는 알고 있었지만 문제를 보면 습관적으로 리스트부터 만드는 경우가 많았다. 이번 파트에서는 자료구조의 이름보다 **어떤 연산을 몇 번 수행하는지**를 먼저 확인하는 연습을 했다.

## 자료구조는 자주 쓰는 연산을 기준으로 고른다

파이썬에서 자주 사용하는 자료구조를 연산 중심으로 정리하면 다음과 같다.

| 자료구조 | 잘 맞는 연산 | 주의할 점 |
| --- | --- | --- |
| `list` | 인덱스 접근, 뒤쪽 삽입·삭제 | 맨 앞 삽입·삭제는 `O(N)` |
| `deque` | 양 끝 삽입·삭제 | 중간 원소 탐색에는 적합하지 않음 |
| `set` | 값의 존재 여부 확인 | 순서를 보장하는 용도로 쓰지 않음 |
| `heapq` | 최솟값 반복 조회 | 임의 원소를 찾거나 정렬된 전체 결과를 볼 때는 추가 작업 필요 |

이 표를 외우기보다 문제에서 반복되는 동작을 적어 본 뒤 가장 비용이 적은 구조를 선택하려고 했다.

## 문제: 백준 2164 카드2

[백준 2164번 카드2](https://www.acmicpc.net/problem/2164)는 1번부터 N번까지 놓인 카드에서 다음 동작을 반복하는 문제다.

1. 맨 위 카드를 버린다.
2. 그다음 카드를 맨 아래로 옮긴다.
3. 카드가 한 장 남으면 그 번호를 출력한다.

맨 위를 큐의 앞, 맨 아래를 큐의 뒤로 보면 필요한 연산은 명확하다.

- 앞에서 제거
- 앞에서 꺼낸 값을 뒤에 추가

두 동작을 모두 `O(1)`에 처리할 수 있는 `deque`가 적합하다.

## 처음 떠올린 풀이와 문제점

처음에는 리스트로도 같은 과정을 구현할 수 있다고 생각했다.

```python
cards = list(range(1, n + 1))

while len(cards) > 1:
    cards.pop(0)
    cards.append(cards.pop(0))
```

결과는 맞지만 `pop(0)`을 실행할 때마다 뒤의 원소를 한 칸씩 앞으로 이동해야 한다. 카드가 많아지면 이 작업이 반복되어 전체 시간이 `O(N²)`에 가까워진다. 문제의 동작을 그대로 옮겼더라도 자료구조가 맞지 않으면 통과하기 어렵다.

## 최종 풀이

```python
from collections import deque

n = int(input())
cards = deque(range(1, n + 1))

while len(cards) > 1:
    cards.popleft()
    cards.append(cards.popleft())

print(cards[0])
```

## 코드 리뷰

```python
cards = deque(range(1, n + 1))
```

1번부터 N번까지의 카드를 순서대로 큐에 넣는다. 별도의 반복문 없이 초기 상태를 만들 수 있다.

```python
cards.popleft()
```

큐의 맨 앞 카드를 제거한다. `deque.popleft()`는 앞 원소를 꺼내는 데 `O(1)`이 걸린다.

```python
cards.append(cards.popleft())
```

다음 카드를 앞에서 꺼낸 뒤 바로 뒤에 넣는다. 문제의 두 번째 동작을 한 줄로 표현했다.

전체 카드는 반복할 때마다 한 장씩 줄어든다. 따라서 시간복잡도는 `O(N)`, 카드 전체를 저장하므로 공간복잡도는 `O(N)`이다.

## 트러블슈팅

### 리스트로도 정답이 나오는데 왜 바꿔야 할까

작은 입력에서는 리스트 풀이도 바로 실행돼 차이가 보이지 않았다. 하지만 코딩테스트에서는 예제 실행 시간이 아니라 최대 입력에서의 연산 횟수를 확인해야 한다. 앞 원소 삭제가 반복된다는 사실을 보고 `deque`로 변경했다.

### 반복 조건을 언제 끝내야 할까

`while cards:`로 작성하면 마지막 카드까지 제거하게 된다. 문제는 한 장이 남았을 때 그 값을 출력해야 하므로 `while len(cards) > 1:`이 정확한 종료 조건이다.

### 마지막 값을 `popleft()`로 출력해도 될까

가능하지만 출력만을 위해 큐를 변경할 필요는 없다. `cards[0]`으로 남은 값을 읽으면 마지막 상태가 그대로 유지되어 의도가 더 분명했다.

## 정리

이 문제의 핵심은 큐를 알고 있는지가 아니라, **앞에서 삭제하는 연산이 반복될 때 리스트와 deque의 비용이 다르다는 점을 판단하는 것**이었다. 이후 자료구조 문제를 풀 때는 코드를 쓰기 전에 삽입, 삭제, 탐색이 어느 위치에서 몇 번 일어나는지부터 적어 보고 있다.
